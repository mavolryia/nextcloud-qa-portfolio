# Тест-план: Nextcloud Files

## 1. Цель и объект тестирования

**Объект:** приложение «Файлы» (Files) в Nextcloud Server 35.0.2 (до 2026-11-11 версия 34.0.5). Это самостоятельно размещаемое облачное хранилище файлов.

**Цель:** проверить, что основные сценарии работы с файлами работают в соответствии с официальной документацией и ожиданиями пользователя, а найденные дефекты оформить и передать сообществу Nextcloud через GitHub.

**Пользователь:** сотрудник организации, который хранит рабочие файлы и делится ими с коллегами и внешними людьми, и для которого важна сохранность и конфиденциальность данных.

## 2. Объём тестирования

### Входит

**Функции:**
- загрузка и скачивание файлов;
- папки: создание, переименование, перемещение, копирование;
- удаление и корзина (восстановление, окончательное удаление);
- просмотр файлов (картинки, текст, PDF);
- избранное и поиск;
- общий доступ: пользователю, группе, публичной ссылкой (в том числе с паролем и сроком действия);
- версии файлов;
- квота (поведение при нехватке места);
- настройки администратора, влияющие на работу с файлами: запрещённые расширения, символы и имена, режим совместимости имён с Windows, квота.

**Роли:**
- обычный пользователь;
- администратор группы;
- администратор сервера (в части, касающейся файлов и пользователей);
- анонимный посетитель (публичная ссылка без входа).

### Не входит

| Что | Причина |
|---|---|
| Другие приложения (Календарь, Talk, Notes и др.) | Не объект этого этапа |
| Редактирование документов в браузере (Nextcloud Office) | Требует отдельного сервера |
| Мобильные и десктопные клиенты синхронизации | Отдельные продукты |
| Нагрузочное тестирование | Нет ресурсов и реальной нагрузки |
| Тестирование безопасности (пентест) | Права доступа проверяются, атаки нет |
| Шифрование, внешние хранилища, федерация | Продвинутые функции, возможно позже |
| Safari | Нет доступа к macOS / iOS |
| Microsoft Edge и другие браузеры на Chromium | Тот же движок (Blink), что у Chrome |

## 3. Подход

Тестирование ручное, в два этапа.

**Этап 1. Интерфейс (веб-версия):**
1. **Смоук-тестирование**: проверка критического пути в начале каждой сессии и после каждого изменения стенда. Если смоук не пройден, дальнейшее тестирование не проводится.
2. **Функциональное тестирование по чек-листам**: проверка функций из раздела «Объём», включая негативные проверки (недопустимые данные, граничные значения). Проводится в два слоя:
   - **по умолчанию**: сервер без дополнительных настроек, как после установки;
   - **конфигурационное**: с изменёнными настройками администратора: по одной-две проверки на каждый тип настройки, чтобы убедиться, что механизм работает (без перебора всех комбинаций).
3. **Тест-кейсы**: для самых важных сценариев: общий доступ и права ролей.
4. **Исследовательское тестирование**: поиск дефектов вне чек-листов по принципу «а что, если…».
5. **Кросс-браузерное тестирование и проверка адаптивности**: основные сценарии в Chrome и Firefox (разные браузерные движки: Blink и Gecko) и на узком экране (DevTools).

**Этап 2. API (Postman):** проверка тех же функций через OCS API и WebDAV.

**Повторное тестирование**: после исправления найденных дефектов в новых версиях Nextcloud.

## 4. Окружение и тестовые данные

### Окружение

| Компонент | Значение |
|---|---|
| ОС | Windows 11 Pro |
| Развёртывание | Docker Desktop 29.9.2 (WSL2), Docker Compose |
| Nextcloud | 35.0.2 (образ `nextcloud:35.0.2-apache`, PHP 8.5) с 2026-11-11; до этого 34.0.5. Резервная копия 34.0.5: `C:\nextcloud-test-big\backup-34.0.5\` |
| База данных | MariaDB 11.4 |
| Фоновые задачи | Cron, отдельный контейнер (`/cron.sh`), каждые 5 минут, с 2026-11-09; до этого режим AJAX |
| Адрес стенда | http://localhost:8080 |
| Браузеры | Google Chrome 156 (основной), Mozilla Firefox (будет установлен) |

Точные версии браузеров фиксируются в каждом баг-репорте.

### Тестовые данные

**Базовые аккаунты** (пароли хранятся отдельно, не в репозитории):

| Аккаунт | Роль |
|---|---|
| admin | Администратор сервера |
| user1 | Администратор группы `users` |

Дополнительные пользователи и группы создаются по мере необходимости и описываются в тест-кейсах.

**Тестовые файлы:** набор файлов разных типов (изображения, текст, PDF, файл без расширения, большой файл) и имена с особыми символами (кириллица, пробелы, эмодзи, длинные имена). Конкретные данные указываются в чек-листах и тест-кейсах.

Стенд можно в любой момент вернуть в исходное состояние (`docker compose down -v`).

## 5. Критерии начала и окончания

### Критерии начала
- Стенд развёрнут, смоук-тестирование пройдено (сборка стабильна).
- Доступна официальная документация Nextcloud (User Manual, Admin Manual) как источник ожидаемого поведения.
- Тест-план согласован, чек-листы для этапа подготовлены.

### Критерии окончания
- Все функции из раздела «Объём» покрыты чек-листами, и все проверки выполнены.
- Тест-кейсы по общему доступу и правам ролей выполнены.
- Каждый найденный дефект проверен на дубликат и оформлен как issue на GitHub (или дополнен существующий).
- Подготовлен итоговый отчёт о тестировании.

## 6. Риски

| Риск | Как снижаем |
|---|---|
| Нет формальных требований, документация неполная или противоречивая | Ориентироваться на документацию, поведение аналогов (Google Drive, Яндекс Диск) и здравый смысл; спорные случаи уточнять в обсуждениях на GitHub; противоречия в документации оформлять как дефекты документации |
| Выход новой версии Nextcloud во время тестирования: тестируемая версия устаревает, найденный дефект может быть уже исправлен | Перед оформлением дефекта проверять его на актуальной версии; обновлять стенд и проходить смоук |
| Найденный дефект уже известен (дубликат) | Перед оформлением искать среди существующих issues |
| Ограниченные ресурсы стенда (7,4 ГБ ОЗУ) | Не устанавливать лишние приложения, останавливать контейнеры после работы |
| Сбои стенда (Docker, WSL, гипервизор) | Инструкция по запуску и типовым проблемам; данные в томах, стенд пересоздаётся за минуты |
| Ограниченное время тестировщика (работа ведётся параллельно с другими делами) | Небольшие этапы с понятным результатом, приоритет: смоук и самые важные функции |
| Долгий ответ или отсутствие ответа от разработчиков на оформленные дефекты | Не влияет на критерии окончания: результат: оформленный дефект, а не его исправление |
